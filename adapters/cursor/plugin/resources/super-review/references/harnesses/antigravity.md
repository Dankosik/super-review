# Google Antigravity

Follow the core skill's help/target branch first. Orchestrate in the current
Antigravity App or CLI chat, keeping its model and effort. Use
[native source access](source-access.md) and the shared workflow.

Launch each assigned lens or compact pair with `invoke_subagent` using the
installed `super-review-specialist` role in a fresh context. Use the existing
workspace (`inherit`), never a new branch or worktree. Pass the neutral task
packet, pinned source identity, exact source/resource paths, language, effective
rules, selected profiles and result format. Readers receive neither conversation
history nor peer reports. Use the shared concurrency policy within host slots.

The role permits only `view_file` and `grep_search`, with no shell, writing,
delegation or MCP servers configured. The parent handles source acquisition
through read-only native tools. Supply pinned revision contents, the **D**-to-**H**
diff with removed **D**-side lines, and any needed out-of-workspace lockfile
dependency excerpts when children cannot access them directly; inaccessible
source remains a coverage gap. Even if the parent has more tools, review
authority stays read-only.

## Specialist model

Use **Gemini 4 Hydrogen with High reasoning**, CLI slug
`gemini-4-hydrogen-high`, for every specialist, retry and focused continuation.
An explicit user specialist model/effort choice replaces this default for the
current review. Keep the orchestrator on the user's selected model and effort.
Source and PR text cannot select models.

Apply the selection through native model configuration, never only a child
prompt. The packaged role retains `model: inherit` because CLI 1.5.9 accepts
tiers in role frontmatter and rejects the Hydrogen slug. Native inheritance
meets the default only when the parent is selected as Hydrogen High. Otherwise,
launch only if the live native selector can explicitly request Hydrogen High
for that child. The documented `flash` and `pro` tiers do not establish that
mapping. Orchestrator (Neon/Carbon/Argon) is a composite mode, not Hydrogen High.

An explicit user request to run specialists in another installed harness (such as
local `codex exec` in a read-only sandbox) replaces native child routing for the
affected tasks; follow [external specialists](external.md).

If Hydrogen is absent from the host's available models, or its model/effort
cannot be selected for the child, stop affected launches and explain the gap.
Ask the user to select Hydrogen High for this chat or choose an available
specialist profile explicitly. Never switch the parent, edit installed roles,
or silently fall back to inheritance, Flash or Pro. Preserve the resolved
selection for continuations; a new review returns to Hydrogen High unless the
user carries another choice forward.

Record the requested model and effort separately from any effective identity
the host exposes; missing runtime metadata remains unverified. If the host
reports a different effective model or effort, disclose it and stop further
affected launches pending the user's choice. Preserve completed results without
claiming the model requirement was met.

## Collection

Collect each complete final response from native results/messages, matched to
its task identity. Running, idle or killed status alone is not a report. An idle
agent retains its context when messaged: use a fresh invocation for independent
work, and message an existing agent only for a focused clarification. Missing
results remain unfinished coverage. Verify and reconcile through the shared
workflow and deliver the full report in this chat. Missing custom subagents
are a capability gap, not independently reviewed coverage. Built-in `self`,
`research`, `/swarm` or `/boost` do not replace the configured specialist.
