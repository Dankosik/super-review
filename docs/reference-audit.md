## Changes beyond the existing baseline

**Coverage reconciliation.** The baseline records task statuses, but an aggregate
status can conceal omitted members of a grouped task. The workflow now retains
the actual file/symbol membership and reconciles inspected subcoverage. Repeated
results and results for different bytes cannot substitute for a missing scope.
This reuses the existing task header and report table. It neither requests a new
store nor turns every file/lens combination into a separate worker.

**Source positioning.** Verification now separates an incorrect line/path from an
incorrect observation. It matches the expression in its containing symbol, handles
repeated snippets, and labels D/old-path comparison evidence separately from
H/new-path code. A supported observation survives a repairable anchor mistake;
an unsupported claim is not accepted just because a similarly worded line exists.
A verified symbol and distinguishing span can replace unavailable line numbering.
Both output templates express that same location contract.

**Improvement discipline.** Root maintainer guidance points to `evals/README.md`.
The evaluator-only `review-integrity` corpus isolates coverage, result provenance,
positioning and old/new-source decisions. Existing activation, language judgment,
policy and host probes remain relevant; this is not a replacement benchmark.

## Kept intentionally

The core `SKILL.md`, review contract, source acquisition, language contexts,
lenses/profiles, rule IDs, models, reasoning effort and permissions are unchanged.
The production preparation still reads included declarations before delegation;
the historical routing-first experiment is not silently promoted. Zero findings,
small useful improvements, supported structural improvements and unresolved
observations remain valid outcomes under the existing acceptance rules.

The reviewer remains read-only and does not assess bugs, security, tests or
business correctness. Repository maintenance may edit and test this project.
The open Java implementation is not incorporated by this instruction audit.
No dependency, persistent runtime, workflow privilege, release tag or marketplace
change is introduced. Generated Claude/Codex copies carry the canonical changes.

## Evidence boundary

These are targeted instruction changes, not a proof of ideal behavior. The
coverage ledger is an instruction-level safeguard, not Alibaba's deterministic
runtime enforcement. Fixture integrity and native-package checks do not measure
recommendation quality, recall, latency or host obedience.

Independent subagent execution and fresh model-backed A/B runs were unavailable
in the authoring session. A single author's separate checks are not independent
reviews. The new corpus is prepared input, not model output; no successful model
run, consensus, quality gain or speedup is claimed. Current validation receipts
belong in the PR for its exact head. Earlier model results retain their original
revisions and limitations.
