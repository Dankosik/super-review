# GPT-6 specialist routing: bounded instruction comparison

This checks only the orchestrator's model-choice decision. It does not run
specialists or assess review quality. The six neutral scenarios are in
`routing-inputs.json`; expected choices are separate in `routing-judgment.json`.
Both runs used the same local Codex CLI 0.153.4, ChatGPT account, evaluator model
`gpt-5.6-sol` at `low` effort, read-only `/tmp` workdir, and no review-source
execution. Each was a fresh ephemeral CLI session. The baseline applied the
3.4.0 profile rule; the candidate applied the 3.5.0 task-selection rule.

| Run | Raw final output | Result |
| --- | --- | --- |
| Baseline | `routing-baseline-2026-09-23.json` | Five tasks selected Terra/medium; the explicit override selected Sol/high. |
| Candidate | `routing-candidate-2026-09-23.json` | All six choices matched the separate judgment file: one bounded Luna, four complexity/uncertainty Sol, one explicit Sol/high. |

The candidate preserved the explicit override and moved a focused continuation
to Sol when its question became a public contract check. This is one run per arm,
not a variance or review-quality estimate. CLI startup hooks added roughly 23k
and 26k reported tokens respectively; those figures are not specialist costs.

The direct `gpt-6-sol` CLI probe failed before inference: this local CLI reported
unknown model metadata, then the ChatGPT-account endpoint returned HTTP 400,
`The 'gpt-6-sol' model is not supported when using Codex with a ChatGPT account.`
A probe with `--ignore-user-config` returned HTTP 401 because the needed auth was
absent. No GPT-6 specialist judgment or live review was measured. The Codex app
exposes the new IDs through its native spawn schema, but effective task routing
and quality on those models remain unverified. Claude Code 2.1.280 validated the
generated plugin manifest; a direct Opus smoke run could not start because the
local OAuth session was expired and refresh failed. No live Opus review was run.
