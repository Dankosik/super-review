## Recommendations

### R-001 — Represent the decoder's *active* phase explicitly

**Location:** frozen `codec/src/lib.rs`, `Decoder` fields and the `push`/`finish` branches distinguished by `self.pending.take()`, `self.count.take()`, `self.ended`, and `self.failed`. **Origin:** F1, with its exclusivity claim corrected.

The active decoder alternates between reading a count, awaiting that count's value, and draining a reserved run. Its two `Option` fields and two terminal booleans leave these relationships implicit across `push` and `finish`; a reader must check branch order to see why an active pending run and a count awaiting a value cannot coexist. A private data-carrying phase with active variants and `Ended`/`Failed` would put that relationship in one place and make transitions inspectable. Keep `reserved` and `max` separate: reservation occurs on acceptance of a complete pair, before its bytes are emitted. Preserve zero-budget no-op for active phases, pending-output priority, the exact consumed count, first-error terminal transition and discarded current batch, successful end-marker behavior, and `finish` semantics. The current early terminal checks and simple loop are a reasonable compact alternative; the benefit is the removal of cross-field state knowledge, not a line-count reduction.

F1's assertion that *all four fields are mutually exclusive at every point* is false. `finish` sets `failed` while a partial count or pending run may remain; a nonempty `push` after an end marker sets `failed` while `ended` remains true. These stale fields are harmless because `failed` is checked first, but an enum must model the terminal transition rather than assume the original claim.

### R-002 — Keep parsed CSV fields as text from the validated input

**Location:** frozen `csv/src/main.rs`, `project`'s `std::str::from_utf8(input)` and `parse`'s `input.as_bytes()`, `field: Vec<u8>`, and two `String::from_utf8(field).map_err(|_| Error::Csv)` boundaries. **Origin:** F2.

`project` validates the *entire* input as UTF-8 before parsing. `parse` then copies bytes from that valid string, removing only ASCII CSV syntax and replacing doubled ASCII quotes with one ASCII quote. Thus each assembled field is valid UTF-8, yet the two fallible conversions make a reader re-prove that invariant and imply a possible `E_CSV` path for field encoding. Traverse the validated string by characters and collect the current field in `String`, retaining the existing CSV state machine and whole-document parse-before-output structure. This makes text validity local to the type while removing the impossible per-field conversion errors. Byte traversal is a legitimate fit for the ASCII delimiters and preserves Unicode bytes naturally; the recommendation is warranted by the duplicated validity reasoning, not by a general preference for character loops. The rewrite must retain exact Unicode field values, quote and CRLF handling, blank records and trailing fields, error precedence (`E_INPUT` before `E_CSV`), withheld stdout on invalid input, and output encoding. It need not change `project`'s byte output buffer.

The recommendations affect independent crates and have no ordering dependency. No external contract or public API change is proposed.
