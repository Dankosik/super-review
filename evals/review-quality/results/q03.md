## Recommendations

### R-001 — Capture the worker's owned values directly

**Location:** frozen `src/worker.rs`, `launch`, from `let worker = Arc::clone(options)` through the `thread::spawn` closure. **Scope:** local. **Origin:** C2, with C1's duplicate-ownership observation merged.

Copy `options.delay` and clone `options.prefix` before spawning; move those values into the closure, sleep for the copied duration, then format the owned prefix. The current closure keeps the whole `Arc<Options>` only to read a `Copy` duration while separately holding a prefix clone. The resulting capture list says exactly which values the independently living worker uses and removes the extra shared-owner lifetime. C1's alternative—retain the Arc and read both fields from it—also removes duplicate prefix ownership and avoids cloning the string, but keeps the entire options object alive for a worker that needs only these two immutable values. The supplied facts establish no custom drop, mutation, callback, resource, or additional field whose lifetime or later value must be preserved. Keep the returned `JoinHandle<String>`, sleep duration, and formatted result unchanged. C1 and C2 must not be implemented together.

### R-002 — Name the publisher-handle counter for what it counts

**Location:** frozen `src/broker.rs`, `State::brokers` and its uses in `Broker::new`, `Clone for Broker`, and `Drop for Broker`. **Scope:** local. **Origin:** C3.

Rename the private field to `publisher_count` at every use, retaining its synchronized increments, decrement, and zero check. A reader otherwise has to infer that `brokers` counts publisher handles, not all strong owners of the shared state. The separate counter remains necessary: `Subscription::drop` may upgrade its weak reference while the final broker drops, so `Arc::strong_count` would answer a different question. This is a private-name change; it does not alter the public broker interface or the close condition.

### R-003 — Put the common state-close transition in one private method

**Location:** frozen `src/broker.rs`, `Broker::close` and the zero-count branch in `Drop for Broker`, each containing `state.open = false; state.subscribers.clear();`. **Scope:** local. **Origin:** C4.

Add a private `State::close(&mut self)` containing exactly those two statements and call it at the two existing guarded sites. This gives one owner to the drain-and-terminate state transition, so a future change to that transition does not require coordinated edits in both paths. Keep the final-handle condition, current lock scope, and sender-drop/callback timing at those call sites; the helper must not replace the publisher count or add a second close path. The source-supported keep alternative is the current two inline statements, which are individually simple but duplicate the same lifecycle rule. This small helper earns its navigation cost because the rule is shared by two distinct entry paths.

R-002 and R-003 are compatible: the renamed count still guards the final-drop call to `State::close`. R-001 is independent. No further prerequisite or ordered migration is needed.
