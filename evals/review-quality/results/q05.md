## C-q05-1: Validated UTF-8 is converted back into fallible field strings

- Change anchor: `src/main.rs`, `project` and `parse`, frozen local snapshot. `project` first does `std::str::from_utf8(input).map_err(|_| Error::Input)?`, then `parse` calls `input.as_bytes()` and uses `String::from_utf8(field).map_err(|_| Error::Csv)?` when ending fields at commas, record terminators, and EOF. These verbatim expressions distinguish the location; no source line numbers were supplied.
- Basis: `rust.data.make-transformations-visible`; base data-flow coverage, no profile or convention-only rule.
- Observation: The parser scans text already validated as UTF-8, copies its bytes into a field buffer, and then revalidates that buffer three ways along the same operation. Delimiters and quote escapes are ASCII, so this route requires a reader to establish that every field boundary stays on a UTF-8 boundary and every emitted replacement quote is valid. The `Error::Csv` conversion branches appear to represent a new UTF-8 failure even though the preceding `E_INPUT` validation and parser's byte operations preserve that property. This is a small but concrete reading burden in the value's path from stdin to projected text.
- Remedy: Iterate the validated `&str` as characters with lookahead for doubled quotes and CRLF, and accumulate each field in a `String`. The parser would then carry decoded text directly into records and remove the three `String::from_utf8` conversions and their apparent failure paths. The strongest keep alternative is the existing byte scanner: CSV syntax is ASCII and byte iteration makes delimiter checks simple. The proposed character loop still needs the same state transitions and lookahead; its benefit is making the already-established text invariant explicit throughout the operation, not fewer allocations or better performance.
- Preserve: `E_INPUT` must remain the only category for invalid input UTF-8; malformed CSV must still use `E_CSV` and precede header and width checks over the whole document. Keep exact Unicode field text, embedded CR/LF, quote escaping, blank records, and final-terminator behavior. No compilation or behavioral equivalence was verified under this read-only stage.
