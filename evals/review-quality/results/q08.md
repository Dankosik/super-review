## C-q08-1: Decoder phase is spread across mutually dependent fields

- Change anchor: frozen `src/lib.rs`, `Decoder` fields `count: Option<u8>`, `pending: Option<(u8, u8)>`, `ended: bool`, and `failed: bool`; `Decoder::push` branches on those fields and `Decoder::finish` updates `failed`. This is a whole-source observation, so there is no change comparison.
- Basis: `rust.representation.express-concepts`; no convention-only advice.
- Observation: These four fields jointly represent one parsing phase. A count awaiting its value, repetitions awaiting output, a completed stream, and terminal failure are distinct phases, but their exclusivity is maintained by the order of `take`, assignments, and early returns across two methods. For example, a trailing-data error after a previously accepted end marker leaves both `ended` and `failed` true, and `failed` must be checked first on later calls. A maintainer changing either method must reconstruct these allowed combinations and precedence from control flow.
- Remedy: Use one private phase enum for reading a count, awaiting a value with its count, emitting a value with its remaining repetitions, ended, and failed. Match that phase in `push` and `finish`; keep the cumulative cap fields independent. This gives the cross-method state transitions one explicit home and removes the need to coordinate four phase fields. The current fields are small and the existing branches are locally readable, so an enum adds matching and transition code; its benefit is making the cross-method phase and error precedence visible in the representation, not reducing line count. A smaller explanation or helper would leave the representable field combinations in place.
- Preserve: `Decoder::new`, `push`, and `finish` signatures; `Decoded` and `Error` shape; greedy pending-output draining; count retention across calls; zero-budget behavior; end-marker and trailing-data precedence; terminal first-error behavior; and cumulative reservation when a complete pair is accepted. In particular, failure after an ended stream must still make later calls return `Failed`. These are requirements from the supplied task context, not runtime-verified claims.
- Affected files: supplied `src/lib.rs` only. No further consumer context is needed for a private representation change that keeps the public signatures and behavior fixed.
