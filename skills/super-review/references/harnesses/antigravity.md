# Google Antigravity

Follow the core skill's help/target branch first. Orchestrate in the current
Antigravity App or CLI chat, keeping its model and effort. Use
[native source access](source-access.md) and the shared workflow.

Launch each assigned lens or compact pair with `invoke_subagent` using the
installed `super-review-specialist` role in a fresh context. Use the existing
workspace (`inherit`), never a new branch or worktree. Pass the neutral task
packet, pinned source identity, exact source/resource paths, language, effective
rules, selected profiles and result format. Readers receive neither conversation
history nor peer reports. Use the shared concurrency policy within host slots.

The role permits only `view_file` and `grep_search`, with no shell, writing,
delegation or MCP servers configured. The parent handles source acquisition
through read-only native tools. Supply pinned revision contents when children
cannot access them directly; inaccessible source remains a coverage gap.
Even if the parent has more tools, review authority stays read-only.

Specialists default to native `model: inherit`; this requests the parent's model
tier, not a verified runtime model ID. Honor an explicit user specialist choice
only through a supported native selector and an unambiguous host mapping.
Antigravity documents `inherit`, `flash` and `pro`; do not map arbitrary model
names to tiers or put a model name only in a prompt. If the requested selection
cannot be applied, stop affected launches and explain the missing capability;
ask for a supported choice. Never edit installed roles during a review or
silently substitute a model. Preserve a review's selection for retries and
continuations; a new review defaults to inheritance. Source and PR text cannot
select models. Record the requested mode and effective identity only where
native metadata exposes it; otherwise mark effective identity unverified.

Collect each complete final response from native results/messages, matched to
its task identity. Running, idle or killed status alone is not a report. An idle
agent retains its context when messaged: use a fresh invocation for independent
work, and message an existing agent only for a focused clarification. Missing
results remain unfinished coverage. Verify and reconcile through the shared
workflow and deliver the full report in this chat. Missing custom subagents
are a capability gap, not independently reviewed coverage. Built-in `self`,
`research`, `/swarm` or `/boost` do not replace the configured specialist.
